# Day 3 — отчёт: 4 способа рассуждения на одной задаче

Модель: `openai/gpt-oss-20b` (Groq). Задача одна и та же для всех способов.

## Задача

```
Дан массив целых чисел nums = [10, 9, 2, 5, 3, 7, 101, 18].
Найди длину самой длинной строго возрастающей подпоследовательности
(Longest Increasing Subsequence). Ответ должен быть одним числом.
```

Правильный ответ известен заранее: **4** (например, `[2, 3, 7, 101]`).

---

```
(Longest Increasing Subsequence). Ответ должен быть одним числом.
```

**Ответ:**
```

```

## 2) Пошаговое рассуждение

**Промпт (user):** задача + `"\n\nРешай пошагово: распиши ход рассуждений перед финальным ответом."`

**Ответ:**
```
**Шаг 1. Подготовка массива**
nums = [10, 9, 2, 5, 3, 7, 101, 18]

### Вариант 1 – Динамическое программирование (O(n²))

1. Создаём массив dp, где dp[i] = длина самой длинной возрастающей
   подпоследовательности, заканчивающейся на nums[i].
2. Инициализируем каждый элемент dp[i] = 1.

| i | nums[i] | dp[i] (после проверки всех j < i) |
|---|---------|-----------------------------------|
| 0 | 10      | 1 (нет меньших предыдущих)        |
| 1 | 9       | 1 (10 > 9)                        |
| 2 | 2       | 1 (10,9 > 2)                      |
| 3 | 5       | 2 (2 < 5 → dp[2]+1 = 2)           |
| 4 | 3       | 2 (2 < 3 → dp[2]+1 = 2)           |
| 5 | 7       | 3 (5 < 7 → dp[3]+1 = 3, 3 < 7 → 3)|
| 6 | 101     | 4 (7 < 101 → dp[5]+1 = 4)         |
| 7 | 18      | 4 (7 < 18 → dp[5]+1 = 4)          |

Максимальная длина = max(dp) = 4.

### Вариант 2 – Patience sorting (O(n log n))

1. Создаём пустой массив tails.
2. Для каждого x ищем в tails первую позицию pos, где tails[pos] ≥ x
   (бинарный поиск); если нет — добавляем x в конец, иначе заменяем.

| x   | tails после обработки |
|-----|------------------------|
| 10  | [10]                   |
| 9   | [9]                    |
| 2   | [2]                    |
| 5   | [2,5]                  |
| 3   | [2,3]                  |
| 7   | [2,3,7]                |
| 101 | [2,3,7,101]            |
| 18  | [2,3,7,18]             |

Длина tails = 4 → длина LIS = 4.

**Итог**
Самая длинная строго возрастающая подпоследовательность имеет длину 4
(например, [2, 3, 7, 101] или [2, 5, 7, 101]).

Ответ: 4
```

### Критик

**System:** `Ты критик. Укажи на распространённые ошибки в решении этой задачи и дай собственный ответ с обоснованием, почему он верный.`

**Ответ:**
```
Answer: 4

Почему именно 4

Найдем все возможные возрастающие подпоследовательности и выберем самую
длинную.

| Индексы | Элементы | Принадлежит LIS? |
|---------|----------|------------------|
| 0 | 10 | Нет – после него следуют только меньшие числа |
| 1 | 9  | Нет – после него следуют только меньшие числа |
| 2 | 2  | Да – самая низкая точка, с ней можно строить LIS |
| 3 | 5  | Да – 2 < 5 |
| 4 | 3  | Да – 2 < 3, но 3 < 5, поэтому 3 не может идти после 5, но
           может идти после 2 |
| 5 | 7  | Да – 5 < 7, 3 < 7 |
| 6 | 101 | Да – 7 < 101, 5 < 101, 3 < 101 |
| 7 | 18  | Да – 7 < 18, 5 < 18, 3 < 18, но 18 < 101, поэтому 18 не
            может идти после 101 в одной LIS |

Самые длинные подпоследовательности:
1. 2, 5, 7, 101 – длина 4
2. 2, 3, 7, 101 – длина 4
3. 2, 5, 7, 18 – длина 4

Никакая подпоследовательность длиной 5 не существует, потому что после
числа 101 нет большего числа, а после 18 нет большего числа, а 101 нельзя
поставить после 18. Поэтому максимальная длина – 4.

Распространённые ошибки при решении

| Ошибка | Что происходит | Как избежать |
|--------|----------------|--------------|
| Неправильный расчёт индексов | Часто берут подпоследовательность как
  подмножество, а не подотрезок | LIS – это подпоследовательность (может
  пропускать элементы), но порядок сохраняется |
| Запутывание «наиболее длинной» и «наибольшей» | Смешивают LIS с
  "наибольшим" элементом | LIS – это длина, а не значение самого большого
  элемента |
| Не использовать динамическое программирование | Перебор всех комбинаций
  даёт экспоненциальное время | Для n до 10⁵ использовать O(n log n)
  (бинарный поиск) |
| Ошибки в сравнении «строго возрастающей» | Сравнивают ≥ вместо > |
  Каждый следующий элемент должен быть строго больше предыдущего |
| Неправильная инициализация DP | dp[i] = 1, но не обновляют для всех
  j < i | Для каждого i проходить j от 0 до i-1, dp[i] = max(dp[i],
  dp[j]+1) при nums[j] < nums[i] |

Кратко о правильном алгоритме

DP-вариант (O(n²)):
    n = len(nums)
    dp = [1]*n
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j]+1)
    answer = max(dp)

Алгоритм O(n log n):
    import bisect
    tails = []
    for x in nums:
        i = bisect.bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    answer = len(tails)

Для данного массива обе реализации дают answer = 4.
```

## Сравнение

Все 4 способа дали правильный ответ (**4**) — задача оказалась слишком
простой для модели, чтобы разница проявилась в точности числа. Разница —
в глубине и проверяемости обоснования:

| Способ | Ответ | Обоснование |
|---|---|---|
| 1. Прямой | 4 | нет |
| 2. Пошаговый | 4 | оба алгоритма (DP + patience sorting), таблицы трассировки |
| 3. Мета-промпт | 4 | сгенерированный промпт сам попросил модель отвечать голым числом — обоснования нет |
| 4. Эксперты: аналитик | 4 | нет (несмотря на system prompt, требующий обоснование) |
| 4. Эксперты: инженер | 4 | нет |
| 4. Эксперты: критик | 4 | полный разбор + таблица ошибок + оба алгоритма |

**Самый точный и информативный способ — пошаговое рассуждение (2).** Даёт
не только верный ответ, но и трассировку, по которой результат можно
проверить вручную.

Неожиданный результат: **мета-промпт себя не оправдал** — на такой
компактной задаче сгенерированный промпт получился строже исходного
(«верни только число»), то есть 2 вызова дали то же самое, что 1 вызов
прямого способа, без дополнительной ценности.

Панель экспертов сработала неравномерно: system prompt с ролью не всегда
заставляет модель развернуть ответ (аналитик и инженер ответили голым
числом) — сработал только критик, у которого сама роль подразумевает
разбор ошибок, а не просто выдачу результата.
