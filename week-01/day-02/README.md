# Day 2

## Задание

Отправьте один и тот же запрос, но:
- добавьте явное описание формата ответа
- добавьте ограничение на длину ответа
- добавьте условие завершения ответа (stop sequence или явную инструкцию)

Сравните ответы:
- без ограничений
- с ограничениями

Результат: один и тот же запрос с разным уровнем контроля ответа через API.

## Что делает

Отправляет один prompt в Groq дважды — без ограничений и с ограничениями
(строгий JSON-формат, длина, stop sequence) — и печатает оба ответа для
сравнения. Constrained-ответ гарантированно единственное валидное JSON-
сообщение (`response_format` с `strict:true`), а не текст по инструкции.

## Usage

```
export GROQ_API_KEY=...
go run . [-max-tokens N] [-stop STR] [-reasoning low|medium|high|off] <prompt>
```

- `-max-tokens` — ограничение длины ответа в токенах (по умолчанию 600;
  reasoning-токены (даже на `low`) тоже входят в этот бюджет — слишком
  маленькое значение обрывает генерацию до валидного JSON и API вернёт
  `json_validate_failed`)
- `-stop` — stop sequence (до 4 у API, тут используется одна)
- `-reasoning` — `reasoning_effort` модели (по умолчанию `low`); `off` не
  шлёт параметр вообще (falls back на дефолт модели) — `gpt-oss-20b` не
  поддерживает полное отключение reasoning, минимум всегда `low`

Формат constrained-ответа зашит как JSON-схема (`bulletsSchema` в коде):
объект `{"bullets": [string, string, string]}`, строго 3 элемента.
