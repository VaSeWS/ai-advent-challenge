# Day 4 — отчёт: один запрос при temperature 0 / 0.7 / 1.2

Модель: `openai/gpt-oss-20b` (Groq), `max_tokens=600`,
`reasoning_effort=low`. Запрос один и тот же для всех температур, по 3
прогона на каждую.

## Запрос

**System:**
```
Отвечай по-русски. Формат ответа строго такой:
1) Объяснение: один абзац, не длиннее 4 предложений.
2) Метафора: одно предложение, начинается со слова "Метафора:".
Ничего кроме этих двух пунктов не выводи.
```

**User:**
```
Объясни, что такое TCP handshake и из каких шагов он состоит,
и придумай для него метафору.
```

Эталон для проверки точности: три шага — SYN, SYN-ACK, ACK; в ходе обмена
согласуются начальные номера последовательности (initial sequence numbers).

---

## temperature = 0

Все три прогона совпали **дословно**:

```
1) Объяснение: TCP‑handshake — это процесс установления соединения между двумя
компьютерами, состоящий из трёх шагов: клиент посылает SYN, сервер отвечает
SYN‑ACK, клиент подтверждает ACK. После этого оба узла готовы передавать данные.
2) Метафора: Метафора: это как телефонный разговор, где сначала звонящий говорит
«Привет, я готов говорить», затем собеседник отвечает «Привет, я тоже готов»,
и только после последнего «Да, давай поговорим» начинается диалог.
```

- схожесть (Jaccard): **1.00**
- дословно совпавших пар: **3 из 3**

Точность: верно. Формат: соблюдён единственный раз из всех девяти
прогонов — нумерация `1)`/`2)` на месте. Метафора: телефонный звонок,
самая избитая метафора для handshake — модель взяла топ-1 вариант.

Оговорка: детерминизм не абсолютный. В предыдущем прогоне этой же
программы (при `max_tokens=800`) два ответа при `temperature=0` разошлись
в хвосте метафоры. `temperature=0` — это жадный выбор токена, но на стороне
провайдера остаются батчинг и параллельные вычисления, дающие
неповторяемость. Полагаться на побитовое совпадение нельзя даже при нуле.

---

## temperature = 0.7

- схожесть (Jaccard): **0.33**
- дословно совпавших пар: **0 из 3**

Три разные метафоры при одном и том же корректном объяснении:

```
Прогон 1: как бы два знакомых встречаются в парке, первый кидает «привет» (SYN),
второй отвечает «привет, давай поговорим» (SYN‑ACK), и третий подтверждает «да,
всё в порядке» (ACK)...

Прогон 2: это как встреча двух людей, которые сначала поздороваются, затем
подтвердят взаимное согласие и только потом начнут разговор.

Прогон 3: это как если бы два знакомые друг другу написали «привет», получили
ответ «привет» и затем подтвердили, что готовы начать беседу.
```

Точность: во всех трёх прогонах SYN / SYN-ACK / ACK названы верно.
Фактическая часть при 0.7 не поехала — менялись формулировки, не факты.

Формат: начал сыпаться. Прогоны 1 и 2 потеряли нумерацию `1)`/`2)`, хотя
system-промпт её требовал. Прогон 3 нумерацию сохранил.

---

## temperature = 1.2

- схожесть (Jaccard): **0.26**
- дословно совпавших пар: **0 из 3**

```
Прогон 1 (markdown-заголовки вместо требуемой нумерации):
**Объяснение:** ... **Метафора:**
Метафора: это как тройной обмен ключами, где каждый участник сначала передаёт
свой ключ, получает ключ другого, а затем подтверждает, что ключи совпадают.

Прогон 2:
...обмениваются тремя пакетами: SYN, SYN‑ACK и ACK, чтобы установить соединение,
согласовать начальные числа окон и подтвердить готовность обеих сторон...
Метафора: handshake — как подпись двух друзей перед встречей: первый машет
рукой, второй отвечает, и наконец они оба кидают подпись, подтверждая договор.

Прогон 3:
Метафора: Это как два друга, которые сначала «помолвились», потом «подтвердили»
и только потом «пошли в поход» вместе.
```

Точность: скелет SYN / SYN-ACK / ACK устоял во всех трёх, но появились
дефекты:
- прогон 2: «согласовать начальные числа окон» — смешаны две разные вещи.
  Согласуются начальные **номера последовательности**; окно (window size)
  анонсируется, но это не то, ради чего делается handshake.
- прогон 1 нарушил формат (markdown вместо нумерации), прогон 2 — тоже.

Креативность: метафоры действительно новые (обмен ключами, подпись
договора), но качество разъезжается. «Помолвились → подтвердили → пошли в
поход» и «два друга кидают подпись» — это уже не метафора, а набор слов:
три шага не отображаются ни на что понятное читателю.

Отдельно: при более жёстком `max_tokens=300` именно на 1.2 один прогон
вернул **пустой ответ** — высокая температура чаще уводит модель в длинные
блуждания, которые не помещаются в лимит.

---

## Сводка

| | temperature=0 | temperature=0.7 | temperature=1.2 |
|---|---|---|---|
| Точность фактов | верно, 3/3 | верно, 3/3 | скелет верен 3/3, 1 смысловая ошибка (окна vs номера последовательности) |
| Соблюдение формата | 3/3 | 1/3 | 0/3 |
| Креативность | нулевая: топ-1 клише (телефонный звонок) | 3 разные рабочие метафоры | новые образы, но 2 из 3 несвязные |
| Разнообразие (Jaccard) | 1.00 | 0.33 | 0.26 |
| Дословных совпадений | 3 из 3 | 0 из 3 | 0 из 3 |

Ключевое наблюдение: **разнообразие растёт быстрее, чем креативность**.
Переход 0 → 0.7 покупает три полезных варианта; переход 0.7 → 1.2 даёт
ещё немного разброса (0.33 → 0.26), но платит за это форматом и связностью.
Полезная зона у этой модели закончилась примерно на 0.7–1.0.

Второе наблюдение: первым ломается **формат**, а не факты. Уже на 0.7
модель начала игнорировать явное требование нумерации, хотя SYN/SYN-ACK/ACK
называла верно. Если ответ парсится кодом, температуру надо держать низкой
не ради правильности фактов, а ради стабильности структуры.

## Для каких задач какая настройка

**temperature = 0** — когда ответ потребляет программа, а не человек:
- извлечение данных, классификация, разметка, роутинг интентов;
- structured output / JSON по схеме (см. day 2);
- генерация кода и SQL, автодополнение;
- воспроизводимые тесты и оценка промптов: сравнивать две версии промпта
  можно только когда шум сэмплирования выключен;
- фактические справки, где нужен один канонический ответ.

Цена: ответ всегда одинаковый и всегда самый банальный. Если ответ не
понравился, перезапуск не поможет — нужен другой промпт.

**temperature = 0.7** — рабочий диапазон для текста, который читает человек:
- чат-ассистенты, объяснения, обучающие материалы;
- маркетинговые тексты, письма, описания;
- брейншторм, когда нужно несколько *разных, но вменяемых* вариантов;
- любой сценарий «сгенерируй N вариантов и выбери лучший» — при 0 все N
  выйдут одинаковыми.

**temperature = 1.2** — только там, где новизна ценнее корректности:
- художественные тексты, поэзия, юмор, нейминг, слоганы;
- генерация синтетических данных, где нужен разброс, а не типичный случай;
- расширение списка идей, когда 0.7 выдаёт одно и то же;
- поиск нестандартных гипотез с обязательной последующей проверкой.

Для фактических задач и любого машинно-читаемого вывода 1.2 не годится:
в этом же тесте она дала смысловую ошибку и сломала формат во всех трёх
прогонах.

**Практическое правило:** начинать с 0 (или 0.2), поднимать только когда
ответы объективно слишком однообразны для задачи. Температура не делает
модель умнее — она только расширяет распределение, из которого берутся
токены, а вместе с удачными вариантами в него попадают и неудачные.
