# Видео-демо дня 33

Сценарий демонстрирует локальный помощник iRon на синтетических обращениях. Это демонстрация помощника, а не запуск или проверка iRon в Windows; реальная аутентификация также не проверялась.

## Подготовка и запись

1. Из корня репозитория задайте `DEEPSEEK_API_KEY` и запустите сервис командой `go run ./week-07/day-33`, как описано в [`../README.md`](../README.md). Оставьте сервис работающим и убедитесь, что доступен `http://127.0.0.1:8033`. Ответы в записи генерируются настоящим запросом к DeepSeek; без доступного ключа запрос чата завершится ошибкой. Приложение не загружает `.env`.
2. Перед записью проверьте, что эксклюзивная блокировка `.omp/task-execute/runs/.screen-recording.lock` свободна. Если файл существует, не удаляйте и не заменяйте его: дождитесь освобождения блокировки. Сценарий не устанавливает и не снимает блокировку.
3. Откройте `week-07/day-33/video/demo.js` в browser eval-среде omp с глобальным `browser`. Нужны операции `browser.open`, `tab.recordStart`, `tab.recordStop`, `tab.recording`, `tab.run`, `tab.fill`, `tab.click`, `tab.waitForSelector`, `tab.waitForText`, `tab.evaluate` и `tab.close`.
4. Загрузите содержимое `demo.js` как строку `source` в eval-контексте, получите объявленную в нём функцию и вызовите её с объектом браузера и реальным путём сохранения MP4:

```js
const recordIronSupportDemo = new Function(
  source + "\nreturn recordIronSupportDemo;",
)();
await recordIronSupportDemo(browser, "/абсолютный/путь/day-33-demo.mp4");
```

Если среда не позволяет передать исходник строкой, скопируйте в eval весь файл `demo.js` целиком и вызовите `await recordIronSupportDemo(browser, "/абсолютный/путь/day-33-demo.mp4")`. Функция не запускается автоматически. Аргумент `source` — текст файла, а не путь к нему. Вспомогательные функции нужно загрузить вместе с основной функцией. Callback-и `tab.run` не захватывают внешние переменные; паузы сценария выполняются вне них.

Сценарий открывает настоящую страницу с viewport 1600×1100 по адресу `127.0.0.1:8033`, начинает запись, очищает `sessionStorage` только этой вкладки и перезагружает приложение для чистой сессии. Таймауты `waitForSelector`, `waitForText` и Puppeteer `waitForFunction` задаются в миллисекундах (`60000` — 60 секунд), а `tab.run` — в секундах. При успехе функция возвращает метаданные рекордера. При ошибке она пытается остановить запись, сохраняет файл без публикации, пробрасывает ошибку вызывающему коду и в любом случае пытается закрыть вкладку.

Сценарий записывает только вкладку с реальной страницей приложения и фактическими ответами сервиса; запись экрана терминала или исходников не нужна. Не подменяйте содержимое страницы, не используйте фиктивные ответы и не вводите ключ API в браузер.

## Сценарий (четыре кадра)

1. **IRON-101:** исходный контекст обращения с `ghost: off`, без отправленного вопроса.
2. **Документированный ответ:** спросить «Почему не отображается пунктирный график Delta?», дождаться ответа, показать найденные источники и наблюдения.
3. **IRON-102:** тот же вопрос при неизвестном значении `ghost`; показать, что помощник запрашивает недостающую конфигурацию, а не угадывает её.
4. **Продолжение IRON-102:** сообщить «В config.json стоит ghost: off. Как включить сравнение с последним кругом?» и показать ответ с основаниями.

После визуальной проверки обзорной сетки и кадров на отметках 38 и 70 секунд видео опубликовано: H.264, 1600×1100, 30 fps, 94,67 с, без звука. [Смотреть видео](https://yadi.sk/d/MTFZQbZ1T2Py_A). Файл загружен командой `bash .claude/skills/record-task-demo/scripts/upload_yadisk.sh week-07/day-33/video/day-33-demo.mp4`, которая использует локальный MCP Яндекс Диска; после успешной публикации загрузчик удалил локальный MP4.
