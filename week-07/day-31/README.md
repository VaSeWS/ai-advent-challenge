# День 31 — помощник разработчика Foodgram

## Задание

Создать CLI-помощника для разработчика существующего проекта Foodgram. Помощник должен искать подтверждения в документации и актуальных сведениях проекта, а затем отвечать на русском языке с точными ссылками на источники. Необходимо поддержать интерактивный режим, ответ на один вопрос, просмотр доступных источников и MCP-сервер для подключения MCP-клиента.

Реализация использует лексический retrieval по документационному корпусу и Groq Chat Completions для формулировки ответа. Это не семантическая векторная база и не проверка работающего приложения: MCP сообщает только живые Git-данные и ограниченный список путей. Корпус формируется из текстовых фрагментов размером не более 2000 UTF-8 байт с границами по строкам; диапазон строк каждого фрагмента сохраняется. Строка источника длиннее лимита приводит к ошибке загрузки, а не обрезается. Документация передаётся модели как недоверенный контекст.

## Запуск

Из корня репозитория:

```sh
git clone https://github.com/VaSeWS/foodgram-project-react.git ../foodgram-project-react
export GROQ_API_KEY='…' # задать значение в окружении, не в исходниках
# Интерактивный режим
go run ./week-07/day-31 -project /путь/к/foodgram-project-react
# Один вопрос
go run ./week-07/day-31 -project /путь/к/foodgram-project-react /help "Как устроена структура проекта?"
# Только retrieval, без API-ключа и LLM
go run ./week-07/day-31 -project /путь/к/foodgram-project-react -search "количество и единица ингредиента"
# Диагностика корпуса и MCP без API-ключа
go run ./week-07/day-31 -project /путь/к/foodgram-project-react -inspect
# Режим MCP stdio для MCP-клиента
go run ./week-07/day-31 server -project /путь/к/foodgram-project-react
```

Флаги располагаются перед позиционным вопросом. Модель по умолчанию — `qwen/qwen3.8-27b`; изменить её можно флагом `-model`. Автоматического fallback нет. Интерактивные команды: `/help <вопрос>`, `/help` (справка), `/exit`.

`GROQ_API_KEY` читается только из переменной окружения. Программа не загружает `.env`, не повторяет запросы и не переключает провайдера. Для `/help` корпус перечитывается, а состояние Foodgram получается заново через MCP на каждом вопросе; изменения документации и ветки видны при следующем запросе. В текущей учётной записи наблюдался лимит 8000 токенов в минуту; это ограничение окружения, а не универсальная константа Groq. Поэтому демонстрационные обращения намеренно разделяются по времени; программа не делает автоматических повторов.

Корпус ограничен `README.md`, Markdown-документами из `docs/` и `docs/openapi-schema.yml` внутри Foodgram. Символические ссылки, скрытые, служебные и чувствительные пути исключаются. `-search` выбирает до 5 поисковых фрагментов, `/help` — до 6; к ним добавляется полное замыкание локальных OpenAPI `$ref`. Оба режима используют один корпус и алгоритм BM25. Текст выбранных фрагментов не обрезается.

Модель возвращает JSON с `answer` и числовыми `source_ids`. Программа проверяет формат, непустой ответ, существование и уникальность ID, а затем сама печатает точные пути и диапазоны строк. Ссылки формирует программа, а не модель; это не доказывает семантическую истинность ответа. Пустой список источников допустим для отказа или ответа только по MCP.

MCP возвращает до 120 путей с признаком ограничения; в prompt передаётся явно обозначенная частичная выборка примерно до 1500 символов. Содержимое этих файлов не читается. Для Groq принимается только завершённый ответ (`finish_reason: stop`); HTTP-ошибки и некорректные ответы завершают программу без повторов и вывода сырого API-тела. Ключи, дампы и приватные данные в документационный корпус не добавляйте.

## Проверка и статус

Проверено: `go test ./...`, `go build ./...`, синтаксис demo.sh и Python-презентера. Реальные `/help` через Groq подтвердили структуру проекта, модель ингредиентов, токен-аутентификацию выгрузки покупок, различие PUT/PATCH, отказ на вопрос об оплате и текущую ветку Foodgram через MCP.

Отдельный smoke подтвердил обновление поискового корпуса после изменения документа и выбор заданного Git-репозитория даже при посторонних `GIT_DIR`/`GIT_WORK_TREE`. Отсутствующий ключ и неверный путь дают exit 1. Проверки границ корпуса, рекурсивных ссылок, detached HEAD и JSON-ответов покрыты локальными тестами.

Сам Foodgram и его HTTP-endpoints не запускались: документация описывает исходный код, а не подтверждённое runtime-поведение. Полный dry-run пятикадрового демо с реальными ответами Groq прошёл за 106,84 с. Утверждённое видео записано и визуально проверено: 149,98 с, 2560×1550, без звука. Запись опубликована через локальный MCP Яндекс Диска.

## Демонстрация

`bash week-07/day-31/video/demo.sh` запускается из checkout учебного репозитория с экспортированным `GROQ_API_KEY`. По умолчанию Foodgram ищется в соседнем каталоге; другой путь задаётся через `FOODGRAM_PROJECT`. Скрипт показывает реальные ответы, постранично сохраняет весь вывод и выдерживает минимум 35 секунд между началами модельных запросов. Эти паузы относятся только к видео, а не к CLI.
