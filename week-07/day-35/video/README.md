# Видео-демо дня 35

Браузерная запись панели администратора с настоящим ответом DeepSeek. [Смотреть опубликованное видео](https://yadi.sk/d/oQB_nvVpwMxPmA). Ниже — инструкция повторного запуска: без подмены сети, данных или AI-вывода, без показа исходного кода и ключей.

## Подготовка

1. Получите `DEEPSEEK_API_KEY` отдельно и экспортируйте его в окружение процесса, который запускает сервер. Приложение читает ключ только через `os.Getenv`, само `.env` не загружает. Не вставляйте значение ключа в команду, кадр или лог.
2. Запустите свежий экземпляр приложения на `127.0.0.1:8045`, с провайдером DeepSeek и новым временным файлом состояния вне репозитория, например:

   ```sh
   go run ./week-07/day-35 -addr 127.0.0.1:8045 -provider deepseek -data /tmp/day-35-video-recording.json
   ```

   Для сухого прогона используйте отдельный свежий экземпляр на `127.0.0.1:8046` и другой новый временный файл, например `/tmp/day-35-video-dry-run.json`. Не используйте сохранённое состояние из репозитория и не копируйте запись или dry-run состояние между экземплярами. Сервер должен оставаться запущенным во время соответствующего прогона. Откройте локальный адрес в браузере и убедитесь, что интерфейс доступен.
3. Координатор записи эксклюзивно управляет `.omp/task-execute/runs/.screen-recording.lock` до начала захвата. Не создавайте, не снимайте, не заменяйте и не удаляйте lease самостоятельно; если захват занят, дождитесь решения координатора.
4. Откройте этот файл `demo.js` как текст в browser eval-среде, где доступен глобальный `browser`. Источник должен быть полным содержимым скрипта, включая вспомогательные функции. Получите функцию из текста и вызовите её с **абсолютным** путём вывода:

   ```js
   const recordTournamentDemo = new Function(
     source + '\nreturn recordTournamentDemo;',
   )();
   await recordTournamentDemo(browser, '/абсолютный/путь/day-35-demo.mp4', {
     baseURL: 'http://127.0.0.1:8046',
     record: false,
     pace: 0.02,
   });
   ```

   Это сухой прогон: он использует отдельный свежий сервер на порту `8046`, не записывает видео (`record: false`) и ускоряет паузы (`pace: 0.02`). Для реальной записи используйте сервер на `8045`, новый файл состояния и такие параметры:

   ```js
   await recordTournamentDemo(browser, '/абсолютный/путь/day-35-demo.mp4', {
     baseURL: 'http://127.0.0.1:8045',
     record: true,
     pace: 1,
   });
   ```

   Скрипт не запускается сам по себе. Передавайте `source` как текст файла, не как путь. Используйте разные временные файлы состояния для каждого нового прогона, чтобы форма и турниры начинались с чистого состояния.

## Сцены

Следуйте пяти сценам в [`scenario.md`](scenario.md), общей длительностью около 166 секунд: исходный шаблон и расписание; настоящий ответ DeepSeek с правкой; отдельное применение и сохранение; RRULE, секундные смещения и предпросмотр; ручное создание двух турниров и неизменность снимков после изменения исходного описания раунда. Показывайте только фактические результаты интерфейса. Если AI-ответ не соответствует запросу или действие не удалось, не скрывайте это и не изображайте успешный результат.

## После записи и публикация

После успешного завершения записи проверьте фактический MP4 через `ffprobe` и предварительный просмотр кадров, включая обзорную сетку. Не считайте незавершённую или не прошедшую финализацию запись успешной и не загружайте её. Затем опубликуйте только видео стандартным репозиторным загрузчиком из корня репозитория:

```sh
bash .claude/skills/record-task-demo/scripts/upload_yadisk.sh week-07/day-35/video/day-35-demo.mp4
```

Загрузчик использует локальный Yandex MCP uploader; не заменяйте его прямым запросом к API или другим загрузчиком. Не сообщайте ссылку или метаданные до получения фактического результата. MP4 игнорируется Git; инструкции и сценарий — отслеживаемые файлы.
