# День 35 — администрирование турниров

## Задание и результат

Задание дня — создать приложение с AI, написать код и подготовить видео. Здесь это локальная демонстрация панели администратора: редактирование шаблона и расписания турнира, просмотр будущих запусков, ручное создание выбранных турниров и чат-помощник для подготовки конфигурации. AI получает текущую конфигурацию и сообщения чата через выбранный внешний API и может задать уточняющий вопрос или предложить проверяемый вариант. Он сам не меняет форму, не сохраняет данные и не создаёт турниры.

Это самостоятельное учебное демо, а не подключение к рабочим системам. [Видео с реальным DeepSeek](https://yadi.sk/d/oQB_nvVpwMxPmA): настройка через чат, ручное создание турниров и проверка неизменности снимков.

## Запуск

Команды выполняются из корня репозитория. Сервер по умолчанию использует Groq; для финального запуска выберите DeepSeek:

```sh
export DEEPSEEK_API_KEY='ваш_ключ_deepseek'
go run ./week-07/day-35 -provider deepseek -data week-07/day-35/data/state.json
```

Для отладки с Groq:

```sh
export GROQ_API_KEY='ваш_ключ_groq'
go run ./week-07/day-35 -provider groq -model openai/gpt-oss-120b -data week-07/day-35/data/state.json
```

Откройте <http://127.0.0.1:8035>. Можно оставить экспортированными оба ключа: приложение использует ключ выбранного `-provider`. Ключи читаются только через `os.Getenv`; Go-код не загружает `.env`. Без ключа доступны панель и ручное управление, но чат не сможет вызвать API.

`-addr` по умолчанию — `127.0.0.1:8035`; сервер привязан к localhost. `-data` — путь к JSON-хранилищу, разрешаемый относительно текущего рабочего каталога; выше указан путь из корня репозитория, чтобы не создавать `data/state.json` в корне. По умолчанию `-data` равен `data/state.json`. `-provider` принимает `groq` (значение по умолчанию) или `deepseek`; `-model` необязателен. Модели по умолчанию: Groq `openai/gpt-oss-120b`, DeepSeek `deepseek-chat`.

Используются Groq Chat Completions API и DeepSeek Chat Completions API. Приложение не показывает ключ браузеру и не сохраняет его. Не вставляйте секрет в интерфейс или публикуемую команду.

## Работа с турнирами

1. Во вкладке «Шаблон» редактируются название, описание, число игроков, бесплатный вход или билет, раунды и награды. Для билета требуется явный ID.
2. Во вкладке «Расписание» задаются локальный DTSTART, IANA-часовой пояс и RRULE. Смещения регистрации — знаковые **секунды** относительно начала события: `-86400` — сутки, `-3600` — час. Допустимы `open <= close <= 0`.
3. Сохранение обновляет текущую конфигурацию в указанном JSON-файле. Если файла ещё нет, используется встроенный пример [`examples/config.json`](examples/config.json); повреждённое состояние не подменяется примером.
4. Предпросмотр показывает не более 50 запусков. Создание происходит только после выбора строк и отдельного ручного подтверждения; фонового планировщика нет.
5. Каждый созданный турнир сохраняет копии шаблона и расписания. Последующие изменения не переписывают эти снимки; повторное создание с теми же ID расписания и временем старта отклоняется.
6. Чат предлагает конфигурацию и список изменений либо задаёт уточняющий вопрос. Предложение отдельно применяется к форме, сохраняется и создаётся только отдельными действиями пользователя. Устаревшая ревизия не должна применяться.

## Форматы и ограничения

- JSON Schema для `Template`, `Schedule` и `Tournament` находится в [`schemas/`](schemas/); полный пример конфигурации — [`examples/config.json`](examples/config.json). Неизвестные поля запрещены.
- Формат шаблона использует накопление очков. При равенстве мест каждый участник получает полную награду соответствующего места (`shared_place_full_reward`), а не долю общего фонда.
- RRULE поддерживает ограниченный поднабор: `DAILY` или `WEEKLY`, `INTERVAL`, `BYDAY` только для недельного расписания и один ограничитель `COUNT` либо `UNTIL`. Расширения не поддерживаются; перебор ограничен 10000 шагами для `COUNT` и `UNTIL`. Предпросмотр ограничен 50 результатами. Локальные времена учитывают DST, несуществующий DTSTART отклоняется, `UNTIL` трактуется как UTC.
- DTSTART хранится как локальная дата-время вместе с часовым поясом. Временные метки с историческим смещением секунд представляются в UTC, чтобы сохранить точный момент времени.
- Хранилище — локальный JSON-файл с одной редактируемой конфигурацией и историей турниров-снимков, не многопользовательская база данных.
- Внешнему AI-провайдеру передаются сообщения чата и текущая конфигурация. Не отправляйте персональные данные, секреты или сведения реальных пользователей. Таймаут запроса — 90 секунд, повторов нет.
- Это локальное демо без публичного сервера, аутентификации, авторизации, проверки оплаты, уведомлений, запуска раундов, фонового планировщика и интеграций с рабочими системами. Не открывайте сервер в публичную сеть.

## API и устранение неполадок

API: `GET /api/state`, `PUT /api/config`, `POST /api/preview`, `POST /api/tournaments`, `GET /api/provider`, `POST /api/chat`. Схемы доступны по `/schemas/template.json`, `/schemas/schedule.json` и `/schemas/tournament.json`. Чат принимает `{config, revision, messages}`; `config: null` в ответе означает уточняющий вопрос.

- **Нет ключа:** экспортируйте ключ выбранного провайдера в окружение процесса до запуска.
- **Ошибка API или модели:** проверьте провайдера, ключ и имя модели; автоматического переключения нет.
- **Предложение не принято:** проверьте ошибки конфигурации и укажите недостающие сведения, например ID билета, часовой пояс или награды.
- **Ошибка файла состояния:** проверьте путь, права и содержимое файла; не удаляйте его, если нужны сохранённые турниры.
- **Пустой или неожиданный предпросмотр:** проверьте DTSTART, часовой пояс и поддерживаемые части RRULE.

## Проверка

```sh
go test ./week-07/day-35
go build ./...
node --check week-07/day-35/web/app.js
```

Проверены реальные вызовы Groq и DeepSeek через админку: предложение изменений, отдельное применение к форме и уточнение отсутствующего ID билета. В браузере проверены ручное создание, просмотр снимков, ошибки JSON, синхронизация RRULE и сохранность ручной правки во время ответа AI. После перезапуска проверено сохранение конфигурации и независимость снимков шаблона и расписания. Без API-ключа ручная панель доступна, чат возвращает явную ошибку.
