# День 32 — AI review для iRon_fork

## Задание

Создать автоматизированное AI-ревью pull request для `VaSeWS/iRon_fork`: использовать документацию memory bank и кодовую базу как локальный RAG-контекст, получить полный diff и содержимое изменённых файлов, отправить запрос к Groq и сформировать русскоязычный отзыв с категориями «Ошибки», «Архитектура» и «Рекомендации». Каждый вывод должен относиться к изменённому пути и строке и ссылаться на выбранные фрагменты доверенного источника. Отзыв публикуется в одном помеченном комментарии PR и обновляется при новом head. AI-review job не исполняет код PR; существующий Windows CI отдельно собирает и проверяет его.

## Архитектура

`tools/ai-review` — автономная Go CLI без сторонних зависимостей. `hash` вычисляет идентификатор allowlist-корпуса: `README.md`, Markdown из `memory-bank/`, C++ исходники `src/` и тесты `tests/`. Хэш включает формат и настройки разбиения и точное содержимое отсортированных файлов, но не Git SHA. `index` строит версионированный JSON-индекс с integrity digest, сохранёнными лексическими postings и line-bounded фрагментами до примерно 2000 UTF-8 байт. `search` выполняет локальный лексический поиск по целым фрагментам. `review` требует точные base/head SHA, проверяет совместимость корпуса с индексом, читает diff и файлы как данные, выбирает контекст и запрашивает модель `qwen/qwen3.8-27b` через Groq Chat Completions.

Модель не имеет инструментов. Структура JSON, категории, severity, source ID, пути и строки валидируются; ссылки на изменения и источники формирует программа. Это проверка формы и привязки, а не гарантия семантической истинности или полноты анализа. Неподтверждённые выводы не должны принудительно добавляться. Удалённые файлы цитируются по base revision, остальные изменения — по head. Публикация изменяет только собственный комментарий с маркером `<!-- iron-ai-review -->` и повторно проверяет актуальные base/head перед записью; чтение и запись GitHub не образуют атомарную compare-and-swap операцию, поэтому остаточная гонка возможна.

## Постоянный RAG-индекс

`.github/workflows/rag-index.yml` создаёт индекс только для доверенного `main` (push по релевантным путям или ручной запуск). Артефакт называется `rag-index-v1-<corpus-hash>`, содержит `index.json` и хранится 90 дней. При идентичном хэше workflow находит и переиспользует артефакт успешного индексирующего запуска вместо повторной сборки. В summary отображаются хэш, число файлов/фрагментов, размер и факт reuse. Workflow ревью принимает только совместимый индекс из успешного доверенного main-run; проверка provenance включает репозиторий, workflow, событие, ref, run и срок хранения. Хэш и digest обнаруживают несовместимость/повреждение, но сами по себе не являются криптографическим доказательством происхождения: происхождение подтверждается GitHub Actions run.

## Граница доверия и ограничения хранения

Pull request рассматривается как недоверенные данные для AI-review job: job checkout использует доверенный base SHA, а head загружается как Git-объекты без checkout/исполнения head. Сам GitHub Actions всё равно загружает и выполняет YAML workflow, определённый в PR, по правилам GitHub; кроме того, существующие Windows CI checks намеренно собирают и запускают код PR. Fork PR пропускаются именно job AI-review. **Обычные авторы same-repository PR, имеющие право изменять workflow, считаются доверенными относительно repository secrets; защита не обещает изоляцию секретов от такого автора.** Workflow предоставляет `GROQ_API_KEY` только шагу review. GitHub Actions artifacts автоматически истекают через 90 дней; локальный временный индекс и отчёт находятся в runner temp и удаляются вместе с runner. Нет отдельной долговременной базы ревью или копирования PR-корпуса в постоянное хранилище. Вызов внешней модели передаёт выбранные фрагменты доверенной базы и содержимое/diff изменённых файлов провайдеру; не помещайте секреты в эти файлы. Лимиты размера и отказ при превышении предотвращают молчаливое усечение, но не гарантируют отсутствие чувствительных данных в разрешённом содержимом.

Ключи читаются только из окружения (`GROQ_API_KEY`, `GH_TOKEN` или `GITHUB_TOKEN`); не добавляйте их в аргументы, исходники, README или логи. Локальный Go review API требует `GH_TOKEN` либо `GITHUB_TOKEN` явно в окружении: логин `gh auth` сам по себе не предоставляет токен процессу Go. Same-repo workflow writers имеют доступ к секрету по принятой границе доверия. Нет автоматических повторов/backoff или переключения провайдера; ошибки завершаются явно.

## Настройка и запуск

Требуются Go 1.25+, Python 3 и GitHub CLI `gh` для интерактивного просмотра GitHub. В CI `GROQ_API_KEY` задаётся repository secret. Для локального ревью нужны `GROQ_API_KEY`, аутентифицированный `gh` с правами чтения PR и публикации issue-комментариев, а также экспортированный `GH_TOKEN` или `GITHUB_TOKEN` для Go GitHub API-клиента (одного `gh auth login` недостаточно):

```sh
git clone https://github.com/VaSeWS/iRon_fork.git ../iRon_fork
cd ../iRon_fork/tools/ai-review
export GROQ_API_KEY='значение из защищённого хранилища'
export GH_TOKEN='GitHub token из защищённого хранилища' # требуется локальному Go review API
go run . hash -root ../..
go run . index -root ../.. -sha '<trusted-base-40-hex-sha>' -out /tmp/index.json
go run . search -index /tmp/index.json -query 'delta logic overlay' -top 6
go run . review -root ../.. -index /tmp/index.json -repo VaSeWS/iRon_fork \
  -pr <номер> -base '<base-40-hex-sha>' -head '<head-40-hex-sha>' \
  -publish -out /tmp/review.md
```

В обычном PR-процессе Actions получает совместимый постоянный main-индекс и публикует отзыв автоматически. Не запускайте локальный `index` на недоверенном PR checkout и не используйте PR-артефакты как источник индекса.
