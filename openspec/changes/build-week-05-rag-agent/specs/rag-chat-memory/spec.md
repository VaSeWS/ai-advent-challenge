## Purpose

Позволить вести продолжительный RAG-диалог по GT:NH с сохраняемой историей и явной памятью цели, уточнений, ограничений и терминов, не смешивая сравниваемые варианты ответа.

## ADDED Requirements

### Requirement: Persistent lane-isolated history
Чат SHALL сохранять пользовательские сообщения и ответы локально, разделяя session и lane. Каждая панель SHALL использовать только собственные assistant messages; режим без RAG SHALL не получать evidence из истории другой панели. Перезапуск SHALL восстанавливать выбранную сессию. Изменение сравниваемой пары SHALL создавать новую session, а не переименовывать существующую историю.

#### Scenario: Continue after restart
- **WHEN** пользователь повторно открывает сохранённую сессию
- **THEN** восстанавливаются её история, параметры панелей и task state, без примеси другой сессии

#### Scenario: Compare independent chats
- **WHEN** две панели ответили на один пользовательский вопрос
- **THEN** следующий запрос каждой панели содержит только её собственные предыдущие ответы

### Requirement: Retrieval on every RAG turn
На каждом новом пользовательском вопросе RAG-чат SHALL выполнять новый поиск по выбранному индексу и формировать ответ с учётом найденного контекста. Разрешение ссылок в продолжениях SHALL учитывать собственную историю панели и включённый task state. История SHALL не подменять актуальный retrieval и не объявляться документальным источником.

#### Scenario: Follow-up changes the topic
- **WHEN** пользователь после вопроса об энергии спрашивает о выбранном маршруте обработки руды
- **THEN** новый turn ищет evidence для нового вопроса, а не повторно использует только контекст старого ответа

### Requirement: Explicit task memory
Task state SHALL отдельно от raw history хранить goal, clarifications, constraints и agreed terms. При включённой памяти программа SHALL автоматически извлекать следующее состояние из прежнего state и явных пользовательских реплик, использовать его для поиска и ответа и позволять пользователю просмотреть его. Предположения assistant SHALL не превращаться в пользовательские ограничения или подтверждённые факты wiki.

#### Scenario: User adds a constraint
- **WHEN** пользователь уточняет ограничение оборудования или энергии
- **THEN** оно доступно в task state и влияет на последующий поиск/ответ, включая случаи, когда исходная реплика вышла из bounded raw context

### Requirement: Latest clarification takes precedence
Текущее пользовательское уточнение SHALL иметь приоритет над прежним task state и raw history. Новое явное значение того же ограничения SHALL заменять устаревшее, а новая сессия SHALL не наследовать цель и ограничения предыдущей задачи.

#### Scenario: Correct a prior constraint
- **WHEN** пользователь явно изменяет ранее указанное ограничение
- **THEN** последующие ответы и отображаемый state используют новое значение, не сохраняя старое как одновременно действующее

#### Scenario: Start a new task
- **WHEN** пользователь создаёт чистую chat session
- **THEN** её goal, clarifications, constraints и terms пусты и не влияют на ответы из прежнего диалога

### Requirement: Atomic successful turns
История успешного turn, результаты панелей и обновления task state SHALL сохраняться атомарно. Невалидное извлечение state или ошибка панели SHALL не оставлять частично записанный успешный turn. Недостаточный-context отказ SHALL считаться допустимым результатом диалога и сохранять явно сообщённые пользователем уточнения.

#### Scenario: State extraction fails
- **WHEN** ответы получены, но новое task state не прошло структурную валидацию
- **THEN** прежние messages и state остаются неизменными, а новый turn не объявляется сохранённым

#### Scenario: User clarifies an unsupported question
- **WHEN** пользователь сообщил ограничение, но corpus не позволил ответить на вопрос
- **THEN** отказ сохраняется вместе с допустимым обновлением state без выдуманного источника

### Requirement: Grounded chat and memory comparison
Содержательные ответы RAG-чата SHALL соответствовать grounded policy с источниками и цитатами; отказы SHALL явно показывать отсутствие подтверждающих источников. Программа SHALL позволять сравнить grounded chat без task state и с task state при одинаковых retrieval settings и main-модели. Ограниченный raw context SHALL не приводить к удалению полной сохранённой истории.

#### Scenario: Compare task memory
- **WHEN** пользователь запускает пару grounded chat без памяти / с памятью
- **THEN** обе панели выполняют retrieval и проверяют источники, но только вторая использует извлечённый task state

### Requirement: Two long-scenario evaluations
Результат дня 25 SHALL включать два воспроизводимых сценария по 10–15 пользовательских сообщений каждый, с ответом на каждое сообщение. Сценарии SHALL проверять сохранение цели, накопление и исправление ограничений, источник каждого содержательного ответа и продолжение после перезапуска. Конкретные реплики SHALL определяться позднее по корпусу; оценка SHALL фиксировать фактические потери цели или источников, а не заранее объявлять успех.

#### Scenario: Inspect a completed long scenario
- **WHEN** сценарий выполнен до конца
- **THEN** доступны история, изменения task state и проверки цели/ограничений/источников по каждому turn, включая evidence после перезапуска
