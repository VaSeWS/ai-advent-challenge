## Context

См. proposal.md — Why. Текущий runtime week-02 знает два профиля, оба облачные, оба с обязательной key environment variable, оба с окном контекста, недостижимым в живом диалоге. Клиент уже OpenAI-compatible, а guard переполнения (`CheckContextOverflow`) опирается только на поля профиля, поэтому третий профиль не требует изменений в Agent, Store, стратегиях и TUI.

Проверено эмпирически на Ollama 0.33.3 (M1 Pro, `llama3:latest`):

- `/v1/chat/completions` возвращает `usage` в OpenAI-формате (`prompt_tokens`, `completion_tokens`, `total_tokens`, `prompt_tokens_details.cached_tokens`), то есть существующая нормализация usage работает без изменений.
- `options.num_ctx` через `/v1/...` не применяется: окно берётся из параметров загруженной модели. Управляемое окно даёт только модель, созданная из Modelfile с `PARAMETER num_ctx 2048`.
- При промпте больше окна Ollama не возвращает ошибку: она молча обрезает промпт (в замере — 10000+ токенов промпта превратились в `prompt_tokens: 1036`) и отвечает неверно. Именно этот контраст с guard'ом week-02 и показывает день 8.

## Goals / Non-Goals

**Goals:**

- Переполнение контекста, достижимое обычным диалогом в том же TUI, теми же командами и той же строкой статуса.
- Нулевая стоимость и отсутствие ключей и rate limit для сценариев, где важен объём, а не качество ответа.

**Non-Goals:**

- Точный токенизатор Llama 3: локальный counter остаётся оценкой, авторитетным для учёта остаётся API usage.
- Конфигурируемые endpoint, модель и размер окна: профиль фиксирован, как и два существующих.
- Автоматическое создание модели `llama3-ctx2k` из кода: это шаг установки, описанный в README.

## Decisions

**Профиль, а не отдельный режим.** Локальная модель добавляется как третий `ProviderProfile` и выбирается тем же `-provider`. Альтернатива — отдельный флаг или отдельная программа — потребовала бы второго пути вызова и второго набора учёта; профиль не трогает ни Agent, ни Store, ни TUI.

**Пустая `KeyEnv` вместо фиктивного ключа.** У `local` `KeyEnv == ""`, и `main` пропускает чтение переменной, а клиент не отправляет заголовок `Authorization`. Альтернатива — требовать `OLLAMA_API_KEY=whatever` — заставляла бы пользователя экспортировать бессмысленную переменную и размывала бы правило «ключ только из окружения» для профилей, которым ключ действительно нужен.

**Окно 2048 и резерв 512.** Значения выбраны так, чтобы переполнение наступало за несколько реплик, но не на первой: guard срабатывает при prompt > 1536 токенов. Окно профиля совпадает с `num_ctx` модели `llama3-ctx2k`, поэтому guard и реальное поведение модели говорят об одной и той же границе. Auxiliary max — 256: summary и facts на локальной модели должны укладываться в то же окно.

**Counter `cl100k-approx`.** Токенизатор Llama 3 — byte-level BPE на базе tiktoken со 128k словарём, и `cl100k_base` из уже подключённого omnitoken даёт близкую, слегка завышенную оценку. Альтернатива — adapter-модуль omnitoken для Llama 3 — добавляет зависимость и загрузку словаря ради демо-профиля. Завышение безопасно: guard срабатывает чуть раньше настоящей границы, а не позже. `Exact()` возвращает `false`, и TUI помечает счётчик как estimate.

**Нулевой тариф с tier `local`.** Формат строки стоимости не меняется, `cost=$0.000000` — честное значение для запуска на своей машине, а tier в сохранённом API-вызове отличает локальные записи от `standard`/`peak`/`off-peak` в `/stats`.

## Risks / Trade-offs

- [Модель `llama3-ctx2k` не создана на машине] → Ollama вернёт ошибку модели; README описывает Modelfile, демо-скрипт создаёт модель перед запуском.
- [Ollama не запущена] → запрос завершится ошибкой соединения, программа fail-fast, как и с недоступным облачным API; отдельная диагностика не вводится.
- [`cl100k-approx` расходится с реальным токенизатором] → расхождение видно прямо в строке статуса рядом с API usage, а counter помечен estimate; для биллинга он и так не используется.
- [Качество ответов llama3 8B ниже облачных моделей] → локальный профиль предназначен для сценариев объёма и переполнения, а не для сравнения качества; по умолчанию остаётся `groq`.

## Migration Plan

Изменение аддитивное: существующие запуски `-provider groq` и `-provider deepseek` ведут себя как раньше. Меняется только текст ошибки для неизвестного провайдера. Откат — удаление профиля из карты профилей и ветки пустой `KeyEnv`.
