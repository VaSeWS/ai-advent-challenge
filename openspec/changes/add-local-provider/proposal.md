## Why

Задание дня 8 требует показать три диалога — короткий, длинный и превышающий лимит модели — и то, что именно ломается при переполнении. С Groq (окно 131072) и DeepSeek (окно 1000000) переполнение недостижимо в живом диалоге: его приходится имитировать вставкой заранее сгенерированного блока на ~130000 токенов, что не похоже на реальную работу агента. Локальная модель через Ollama с окном 2048 даёт то же переполнение за несколько обычных реплик, без ключей, без rate limit и без оплаты, и позволяет рядом показать сырой вызов той же модели без guard-проверки: Ollama не возвращает ошибку, а молча обрезает промпт и отвечает неверно.

## What Changes

- Добавляется третий provider profile `local`: OpenAI-compatible endpoint Ollama `http://localhost:11434/v1/chat/completions`, модель `llama3-ctx2k`, окно контекста 2048, main completion 512, auxiliary 256.
- `-provider` начинает принимать `local` наравне с `groq` и `deepseek`; сообщение о неизвестном провайдере перечисляет все три значения. **BREAKING** для текста ошибки `unknown provider`.
- Профиль без ключа: у `local` пустая `KeyEnv`, программа не читает environment variable и не требует её. Профили с непустой `KeyEnv` ведут себя как раньше.
- Локальный счётчик токенов `cl100k-approx` (encoding `cl100k_base` из уже подключённого omnitoken) помечается как estimate: точный токенизатор Llama 3 в проект не добавляется.
- Стоимость профиля `local` — нулевая, pricing tier `local`: запуск на своей машине ничего не стоит, а строка стоимости остаётся в том же формате.
- README week-02 документирует профиль, создание модели `llama3-ctx2k` через Modelfile (`PARAMETER num_ctx 2048`) и причину, по которой переполнение показывается именно на локальной модели.
