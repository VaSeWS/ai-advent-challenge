# День 27 — локальная модель в приложении

Демонстрационное приложение — настоящий TUI-агент из `week-04/agent`, подключённый к локальному OpenAI-compatible HTTP endpoint MLX. Это local-only путь: облачный провайдер и шаблонные ответы не используются. Инструкции, закреплённый Qwen snapshot, настройки и ограничения памяти — в [README дня 26](../day-26/README.md).
Текущий активный snapshot — Qwen3.5-4B-4bit revision `0e7ffd5c629ef7719d4cbc04069232580bfa9d9c`. Ранее записанные три запроса и oracle evidence относятся к историческому Qwen3.8-27B и не принимают новый runtime. Combined history+LIVE provenance должен отличать исходную модель архивных строк от выбранной модели двух новых LIVE API calls.

Запустите локальный сервер по инструкции дня 26, затем из корня репозитория выполните:

```sh
bash week-06/day-26/video/demo.sh
```

Без `DAY26_HISTORY_DB` выполняются три свежих независимых запроса в новой SQLite-базе. Для утверждённого совместного видео задайте `DAY26_HISTORY_DB`: DB и существующие `-wal`/`-shm` байтово копируются в эксклюзивный приватный staging-каталог `0700`; SQLite проверяет и копирует данные только из staged DB, включая записи из WAL. Проверяются исходные prompts, три чата/шесть сообщений/шесть API-вызовов и отсутствие MCP. После `/use 1`, `/use 2`, `/use 3` TUI создаёт `/new Day 26 — LIVE simple` и отправляет исходный простой prompt локальной модели. При успехе clone содержит четыре чата, восемь сообщений (четыре assistant) и восемь API-вызовов; `provenance.json` фиксирует history, LIVE и результат проверки source identity/DB+sidecar bytes после TUI сценария. Источник и sidecars не открываются SQLite и проверяются до/после staging и в финале; symlink, alias, нестабильный источник или смена sidecar presence приводит к ошибке без успешной provenance. Пути `DAY26_HISTORY_DB` и `DAY26_DB` несовместимы.
