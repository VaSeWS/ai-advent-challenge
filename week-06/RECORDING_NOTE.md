# Запись недели 6 — без новых разрешений

**Для записи на текущем Mac в существующем Terminal новые разрешения запрашивать не нужно.** Предыдущие недели записывались в этом окружении; в этой сессии реальный ScreenCaptureKit-захват также успешно выполнен.

- Из non-TTY инструментов использовать штатный native вход `record.sh`: он создаёт собственную свежую вкладку/окно в существующем Terminal через `do script ""`, проверяет live TTY, точный новый window ID и idle shell. Исходные окна пользователя не переиспользуются для запуска демо; их геометрия не меняется. Completed tabs могут сохранять старые TTY, поэтому уникальность считается только среди вкладок с живыми processes.
- Не запрашивать System Events / Accessibility / новые разрешения автоматизации и не отправлять пользователя менять настройки macOS ради записи.
- Использовать `.claude/skills/record-task-demo/scripts/record.sh` из интерактивной вкладки или через его native non-TTY вход. Оба пути сопоставляют TTY с точным window ID и записывают только измеренный текстовый viewport.
- Не включать native tab titles других вкладок, не использовать fullscreen/rectangle fallback, не менять общую геометрию окна. `CAPTURE_WINDOW=0` и `W/H/X/Y` отклоняются.
- Фактический шрифт собственной вкладки — минимум 16 pt; проверенный smoke использовал 18 pt. Во время записи не переключать вкладку и не менять её геометрию или шрифт.
- Исправленный crop проверен реальным видео: первая строка и последняя строка 44 видны целиком, чужих заголовков и чёрной полосы нет. Доказательство: `.omp/task-execute/runs/week06-local-llm-20261011/evidence/capture-measured-surface-20261013.mp4`, кадр на 1 с; независимое focused review принято.
- Пятикадровые планы 26–27 и 29 утверждены; прежний LIVE-план 28 заменён явно утверждёнными тремя SAVED-кадрами. Для 29 стандартная запись прошла exit 0, полный MP4 проверен и опубликован через локальный Yandex Disk MCP: https://yadi.sk/d/a7BxK-c7SLFZRw, фактическая длительность 24 мин 10 с. Утверждение плана — не разрешение обходить execution/ownership guards.
- Общий supervisor теперь эксклюзивно создаёт единый для проекта `.omp/task-execute/runs/.screen-recording.lock` до любого Terminal query/изменения вкладки или профиля, измерения viewport и запуска compiler/recorder/demo. Другой день или путь видео не обходит lock; конкурирующий запуск отказывается от защищённых действий. Очередь повторяется только после подтверждения освобождения владельцем, без polling recorder, timeout stealing и env bypass.
- Lease содержит token, PID, host, task/demo, время и известные lifecycle paths/child PIDs, без credentials. Он удерживается до подтверждённого завершения direct children и private workload; child-exec launcher восстанавливает исходную маску SIGINT/SIGTERM перед запуском workload, сохраняя actual child handles и защиту публикации от pending signals. Освобождение сверяет token и identity файла. Неизвестный stop, crash/SIGKILL или подмена оставляют lock для явного reconciliation. Не заменять lock живого владельца: сначала установить завершение владельца и всех указанных lifecycle; CLI `--permission-preflight` lock не занимает.
- Это кооперативная защита общих recording processes, а не containment hostile процессов: token/identity проверки не делают rename/unlink атомарными против внешнего replacer и не устраняют соответствующий TOCTOU.
- Native IPC и текущий source прошли независимое source review; успешная стандартная запись дня 29 подтвердила полный happy path исходного варианта. Completed-tab TTY исправление отдельно проверено реальным read-only Terminal observer и prelaunch запуском; это не новый полный capture/cancellation proof. Старые частичные/неудачные fixture результаты сохраняются и не объявляются пройденными.
